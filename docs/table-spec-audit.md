# Аудит таблиц по схеме «Оружие / GlobalUI»

Сверка текущей реализации таблиц Meander со схемой из задачи (таблица `Оружие`,
`ID_строки`, `GlobalScript`, динамическая ссылка `[[Eq_W]]`, привязка картинки).

## Коротко

Модель таблиц и переименование строк уже есть. Два элемента схемы — это
**старый синтаксис/старая архитектура**, которых в текущем движке нет
намеренно:

- `[[Eq_W]]` не парсится. Рабочая форма — `[Eq_W]` (переменная) или
  `["Eq_W"]` (литеральное имя строки).
- `GlobalScript` как реестр в `config.json` удалён. Его роль выполняют
  `onQuestStart` и `onDataChange`-скрипты из `scripts/`.

## По пунктам

| Требование схемы | Сейчас | Где |
|---|---|---|
| Сетка: колонки, строки, ячейки | Есть | `QuestTable` (`models/quest_table.rs`, `quest_table.dart`) |
| `ID_строки` как колонка | Обычная колонка таблицы; ничем не отличается от `W_Name` | редактор таблиц |
| Идентификатор/имя строки отдельно от колонок | Есть: `rowNames` — параллельный `rows` список | `QuestTable.row_name` / `rowName` |
| Переименование строки | Есть: меню строки → «Имя строки…»; имя можно убрать | `table_editor_screen.dart`, `_renameRow` |
| Адрес по имени строки | Есть: `{Оружие["W_Name"]["W_Axe_1"]}` | `parse_path`, deep lookup |
| Адрес по переменной | Есть: `{Оружие["W_Name"][Eq_W]}` | `executor.rs`, тест «номер строки из переменной» |
| Адрес по формуле | Есть: `{Оружие["W_Name"][lower("W_AXE_1")]}` | `executor.rs` |
| `[[Eq_W]]` | **Не поддерживается**; двойные квадратные скобки — не часть синтаксиса | — |
| `GlobalScript` / `GlobalUI` | **Удалён намеренно**; список глобальных скриптов больше не хранится в конфиге | `quest_scripts.rs`, `quest_script_events.dart` |
| Непрерывное обновление экипировки | `onDataChange` по переменной `Eq_W` (или по таблице) + присваивания | `engine_tests/data_change.rs` |
| Картинка из таблицы | `resourceExpr` у слоя стека / `set_image`; выражение с таблицей работает | `ContentItem.resourceExpr`, `resolveResourcePath` |
| Вложенные таблицы | Есть | `QuestTable.is_nested_value`, редактор |

## Как переписать пример под текущий движок

Таблица `Оружие`:

```json
{
  "name": "Оружие",
  "columns": ["ID_строки", "W_Name", "W_Type", "W_D_Min", "W_D_Max", "W_D_Bonus", "W_Img"],
  "rowNames": ["W_0", "W_Axe_1"],
  "rows": [
    {"ID_строки": "W_0", "W_Name": "Ничего", "W_Type": "Без оружия", "W_D_Min": 0, "W_D_Max": 0, "W_D_Bonus": 0, "W_Img": "Ресурсы/Png оружие/Ничего.png"},
    {"ID_строки": "W_Axe_1", "W_Name": "Топор", "W_Type": "Рубящий", "W_D_Min": 3, "W_D_Max": 6, "W_D_Bonus": 0, "W_Img": "Ресурсы/Png оружие/Топор.png"}
  ],
  "data": {}
}
```

Кнопка «Экипировать топор»:

```text
Eq_W = "W_Axe_1"
```

Присваивания (вместо GlobalScript):

```text
Eq_W_Name    = {Оружие["W_Name"][Eq_W]}
Eq_W_Type    = {Оружие["W_Type"][Eq_W]}
Eq_W_D_min   = {Оружие["W_D_Min"][Eq_W]}
Eq_W_D_max   = {Оружие["W_D_Max"][Eq_W]}
Eq_W_D_Bonus = {Оружие["W_D_Bonus"][Eq_W]}
```

Картинка:

```text
resourceExpr = {Оружие["W_Img"][Eq_W]}
```

Автоматическое обновление после смены `Eq_W` — скрипт события
`onDataChange` с `watchPaths: ["Eq_W"]`; в нём те же присваивания. Движок
собирает изменения на границе шага, поэтому после нажатия кнопки достаточно
сменить `Eq_W`, а остальные поля обновятся сами.

## Почему `GlobalScript` больше нет

Реестр `globalScripts` в `config.json` убран: движок сам находит скрипты в
`scripts/`, которые объявляют `onQuestStart`/`onDataChange`. Это убирает
рассинхронизацию «скрипт есть, но не подключён» и лишний список в настройках.
Для непрерывной логики используйте `onDataChange`, а не фоновый скрипт.

## Что стоит поправить в схеме

1. Заменить `[[Eq_W]]` на `[Eq_W]` — иначе движок вернёт `null`/пусто.
2. Не хранить `ID_строки` одновременно колонкой и именем строки без
   необходимости: либо колонка, либо `rowNames`. Если нужны оба — держите их
   синхронными (редактор не синхронизирует колонку и имя автоматически).
3. Для картинки использовать `resourceExpr` слоя/`set_image`, а не
   `Value`-поле присваивания: путь — это ресурс, а не переменная.
4. `GlobalScript` заменить на `onDataChange` с подпиской на `Eq_W`.

## Проверки, на которые опирается аудит

- `arbitrary_row_names_survive_placeholder_parsing` — строки с `{...}`,
  кавычками и скобками адресуются как литералы.
- `column_name_wins_over_row_name_in_deep_lookup` — приоритет колонки.
- `table_data_key_watch_fires` — `onDataChange` по ключу таблицы.
- `table_tokens_are_granular_and_cells_are_one_based` — дифф таблицы и
  адресация ячеек.
- `text_outline_survives_roundtrip_and_stays_absent_by_default` — обводка
  текста (см. отдельный пункт задачи).
