# Таблицы

Таблица квеста — сетка «строки × колонки» плюс произвольное key-value
хранилище. Из текста, формул и скриптов к ячейкам обращаются по имени таблицы.

Этот документ закрепляет:
1. [что хранит таблица (формат JSON)](#формат-хранения);
2. [как адресоваться к ячейкам](#адресация);
3. [кавычки и экранирование в именах](#кавычки-экранирование-и-скобки);
4. [что возвращается и в каком виде печатается](#возвращаемые-значения).

## Формат хранения

Канонический JSON (формат `QuestTable::to_json`, Dart-модель `QuestTable`):

```json
{
  "name": "лавка",
  "columns": ["товар", "цена", "остаток"],
  "rows": [
    {"товар": "меч", "цена": 10, "остаток": 5},
    {"товар": "щит", "цена": 20, "остаток": 0}
  ],
  "rowNames": ["меч", "щит"],
  "data": {"открыт": true, "уровень": 3}
}
```

| Поле | Обязательно | Смысл |
| --- | --- | --- |
| `name` | да | имя для адресации в выражениях (`лавка[...]`) |
| `columns` | да | имена колонок, в порядке колонок сетки |
| `rows` | да | массив объектов; ключ объекта — имя колонки |
| `rowNames` | нет | имена строк, параллельно `rows` |
| `data` | нет | произвольные пары ключ→значение, видимые скриптам |

Правила нормализации:

- `rowNames` короче `rows` — недостающие имена пустые; длиннее — лишние
  отбрасываются. Пустая строка означает «у строки нет имени» (доступ по
  номеру продолжает работать).
- Имена строк **обрезаются по пробелам** (`trim`).
- Legacy-таблицы без поля `data`: ключи верхнего уровня, кроме
  `name`/`columns`/`rows`/`rowNames`/`row_names` и любых `__*`, переносятся в
  `data`. Редактор и движок читают оба вида.
- Ячейка может хранить **вложенную таблицу** — объект той же формы
  (`columns` + `rows`). Формулы и адреса видят её как обычную таблицу.

## Адресация

Все три записи означают одно и то же значение:

| Форма | Пример | Где встречается |
| --- | --- | --- |
| `{...}` | `{лавка["цена"][1]}` | текст автора |
| `{{...}}` | `{{лавка["цена"][1]}}` | текст автора, двойная обёртка |
| голый адрес | `лавка["цена"][1]` | «сырой» токен от клиента (`evaluateSync`) |

Пути:

| Адрес | Возвращает |
| --- | --- |
| `t["колонка"]` | вся колонка — массив значений |
| `t["колонка"][N]` | ячейка, `N` — **номер строки, начиная с 1** (как в сетке) |
| `t["колонка"]["имя"]` | ячейка по имени строки (точное совпадение) |
| `t["имя"]["колонка"]` | то же, строка-сначала |
| `t["ключ"]` | значение из `data` |
| `t.колонка`, `t.ключ` | точечный доступ к колонке/`data` |
| `t["rows"]`, `t["columns"]` | сами массивы строк/колонок (зарезервированы) |
| `t["колонка"][N][M]` | внутрь массива ячейки — `M` **с 0** (обычный JSON) |

Особенности:

- **1-based только для строк таблицы** (колонка, `rows`). После того как
  адрес дошёл до строки (`t["колонка"][1]`), значение — обычный JSON, и
  вложенные массивы индексируются **с 0**: `t["дост.доступ"][1][0]`.
- **Колонка важнее имени строки**: если имя колонки совпадает с именем
  строки, `t["X"]` вернёт колонку.
- Зарезервированные `rows`/`columns` нельзя использовать как имя колонки или
  строки — `t["columns"]` всегда вернёт список колонок.
- Ключ сегмента может быть **переменной или формулой**: `t[ключ]`,
  `t["цена"][ключ]`, `t["цена"][upper("меч")]`.
- Имя строки проверяется первым, затем номер: `table_cell(shop, 'цена',
  'меч')` сначала ищет строку с именем «меч».

Промахи всегда дают `null` (в тексте — пустая строка):

- нет таблицы/колонки/строки/ключа;
- номер строки `0`, отрицательный или больше числа строк;
- пустое имя строки (можно обратиться только по номеру).

## Кавычки, экранирование и скобки

Сегмент в `[...]` — строковый литерал или имя:

- `"цена"` и `'цена'` равнозначны; одинарные и двойные кавычки работают
  одинаково.
- Экранирование: `\"`, `\'`, `\\`, `\n`, `\t`, `\r` — в любых кавычках.
- Без кавычек: имя читается до следующего `]` или `.` (точка и `]` в таком
  имени недопустимы).

Скобки и кавычки в **именах строк, колонок и ключей `data`** — это данные, а
не разметка. Внутри кавычек безопасно использовать:

- `[` `]` `.` — скобки адреса и точка;
- `{` `}` — одинарные фигурные скобки;
- `{{` `}}` — двойные фигурные скобки (не схлопываются подстановкой);
- `"` `'` — кавычки (экранируются: `\"`/`\'`);
- `\` — обратный слэш (экранируется: `\\`).

Примеры имён и адресов к ним:

| Имя строки | Адрес |
| --- | --- |
| `меч` | `t["цена"]["меч"]` |
| `{test}` | `t["цена"]["{test}"]` |
| `a}b` | `t["цена"]["a}b"]` |
| `a{{b` | `t["цена"]["a{{b"]` |
| `a'b` | `t["цена"]["a'b"]` |
| `a"b` | `t["цена"]["a\"b"]` |
| `a\b` | `t["цена"]["a\\b"]` |

`{test}` в кавычках — имя строки, а не плейсхолдер: подстановка не трогает
кавычки.

## Функции таблиц (в выражениях)

Номера строк в функциях тоже **с 1**.

| Функция | Возвращает |
| --- | --- |
| `table_rows(t)` | число строк |
| `table_columns(t)` | массив имён колонок |
| `table_column(t, 'цена')` | колонка как массив |
| `table_cell(t, 'цена', 1)` | ячейка по номеру строки |
| `table_cell(t, 'цена', 'меч')` | ячейка по имени строки |
| `table_row(t, 1)` | строка как объект |
| `table_row_names(t)` | массив имён строк |
| `table_row_number(t, 'меч')` | 1-based номер строки, `0` если нет |
| `table_sum(t, 'цена')` | сумма числовой колонки |
| `table_avg(t, 'цена')` | среднее (целое, если сумма делится нацело) |

Промах в `table_cell`/`table_row` (нет таблицы/колонки/строки) → `null`.

## Возвращаемые значения

Ячейка печатается в тексте через `formatScriptValue` (клиент) /
`value_to_string` (ядро):

| Значение | Печать |
| --- | --- |
| `null` | пустая строка |
| число `15.0` | `15` (без `.0`) |
| число `2.5` | `2.5` |
| строка `меч` | `меч` (как есть) |
| `true`/`false` | `true`/`false` |
| массив/объект (колонка, строка, таблица) | строковое представление (`[10, 20]`, `{товар: меч, …}`) |

Для ячеек с числами и строками ничего лишнего не добавляется; для вложенных
структур подставляется их строковое представление, а не JSON со строгими
кавычками ключей.
