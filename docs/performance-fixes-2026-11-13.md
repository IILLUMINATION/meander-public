# Правки производительности: что сделано и почему (2026-11-13)

Ветка: `perf/mobile-performance-fixes`, база — `main` @ `534b299` (2.8.17).
Аудит, на который опираются правки: `docs/performance-audit-2026-11-13.md`.

Документ писался для ревьюера (в том числе ИИ): в каждом пункте — **причина**,
**что изменено** (с файлами), **чем рискует** и **как проверить/откатить**.
Если меняешь код в этих местах — сначала прочитай инварианты в разделе 4.

---

## 1. TL;DR

Две разные болезни, лечатся по-разному:

**A. Лаги на мощных телефонах** — четыре причины, все устранены:

1. приложение само просило максимальную частоту экрана (120 Гц → бюджет кадра
   8,3 мс вместо 16,6);
2. самые дорогие эффекты (полноэкранный гаусс фона в игре) включались **только**
   при памяти ≥ 4 ГБ, то есть ровно на флагманах;
3. RepaintBoundary была одна на всё приложение, а анимации не останавливались
   при уходе с вкладки → перерисовывался весь экран каждый кадр;
4. глобальные socket-события перестраивали ленту, а markdown каждого поста
   парсился заново на каждую перестройку.

**B. Слабый Android 10 (2 ГБ)** — старт блокировался Firebase до 10 с, первый
кадр строил все шесть вкладок, картинки декодировались в полном разрешении
(OOM), автосейв читал весь квест каждые 1,5 с, кэши не были ограничены.

Итого: 35 файлов, +968/−220. Затронуты `apps/main_app`, `packages/mnd_player`,
Android-сборка, CHANGELOG.

## 2. Границы проверки (прочитать до ревью)

- **Запустить приложение и тесты на машине, где делались правки, невозможно**:
  локальный Flutter 3.50 внутренне неконсистентен — не компилируется даже сам
  фреймворк (`ValueListenable isn't a type` в
  `flutter/lib/src/animation/animation.dart`), `flutter test` падает на любом
  тесте. Проект в CI пинится на **3.47.0**
  (`.github/workflows/build_android.yml:23`).
- Поэтому статическая проверка: `dart analyze` по `apps/main_app/lib` и
  `packages/mnd_player/lib` даёт **ровно те же 225/21 error+warning**, что и до
  правок. Все они — артефакты того же несовместимого SDK
  (`ValueNotifier`, `TextEditingController.dispose`, `TextPainter.textDirection`,
  `ScrollController.addListener`), встречаются и в нетронутых файлах.
  Новых диагностик не добавлено ни одной.
- Выполнены реально (чистый Dart, без Flutter):
  `defaultBackgroundBlurFor`, `resolveBackgroundBlur`, `gateBackgroundBlur`,
  `imageDecodeWidthFor` — проверки 1080→1080, /2→540, /3→360, 4000→1440,
  0/NaN→200, `divisor: 0`→1000 прошли.
- **На устройстве ничего не проверялось.** Чек-лист — раздел 6.
- Тесты, добавленные для новых чистых функций: `test/shared/image_sizing_test.dart`,
  `packages/mnd_player/test/utils/background_blur_test.dart` (новая группа

## 3. Изменения по пунктам

### 3.1. Частота экрана: 60 Гц по умолчанию

- **Причина:** `DisplayRefreshRate.kt` просил максимальный режим при
  `getBoolean(PREF_KEY, true)`. На 120 Гц всё, что не влезает в 8,3 мс, начинает
  пропускать кадры — и лагает сильнее, чем на 60-Гц телефоне.
- **Изменено:** `DisplayRefreshRate.kt:84` — дефолт `false`;
  `core/services/display_refresh_rate.dart:39` — тот же дефолт для чтения
  состояния в настройках.
- **Поведение:** «Плавность N Гц» осталась переключателем в настройках
  (`features/settings/widgets/refresh_rate_card.dart`), просто теперь она
  включена только по выбору пользователя. У тех, кто уже трогал переключатель,
  сохранённое значение не меняется.
- **Откат:** вернуть `true` в двух местах.
- **Проверить:** на 120-Гц телефоне сравнить прокрутку каталога и профиля с
  включённой и выключенной «Плавностью».

### 3.2. Неявное размытие фона в игре — только по воле автора

- **Причина:** `defaultBackgroundBlur = 10.0` применялся к каждому узлу с фоновым
  изображением, даже если автор размытие не задавал. `ImageFiltered` на весь
  экран пересчитывает гаусс каждый кадр. На устройствах < 4 ГБ это резалось
  гейтом по памяти — то есть на слабых было резко, на флагманах мыльно и дорого.
- **Изменено:**
  - `packages/mnd_player/lib/utils/background_blur.dart:4-14` — новая функция
    `defaultBackgroundBlurFor(platform)`: `0` для `android`/`ios`, `10` для
    десктопа. `defaultBackgroundBlur` и `resolveBackgroundBlur` не менялись.
  - `packages/mnd_player/lib/screens/game_screen.dart:1846-1852` — в
    `resolveBackgroundBlur` передаётся
    `fallback: defaultBackgroundBlurFor(defaultTargetPlatform.name)`.
- **Поведение:** явно выставленное значение (поле ноды `backgroundBlur` или
  `set_blur` из скрипта) работает как раньше. Меняется только неявный дефолт на
  мобиле.
- **Риск:** квесты, которые «размывали фон, потому что так было по умолчанию»,
  теперь покажут резкий фон на телефоне. Это осознанный продуктовый компромисс;
  если он неприемлем — автор ставит `backgroundBlur` явно.
- **Тесты:** `packages/mnd_player/test/utils/background_blur_test.dart` — новая
  группа `defaultBackgroundBlurFor` (мобильный ноль, десктопный десяток, явные
  значения перекрывают дефолт). Существующие негативные контролы
  `background_blur_wiring_test.dart` не тронуты и продолжают действовать.
- **Откат:** убрать аргумент `fallback:` из `game_screen.dart`.

### 3.3. Скрытые вкладки не крутят анимации; вкладки монтируются лениво

- **Причина:** `IndexedStack` держит всех детей смонтированными, тикеры не гасит,
  и первый кадр shell строил все шесть экранов вместе с их запросами.
- **Изменено** в `features/shell/screens/menu_screen.dart`:
  - `:70-76` — `_mountedTabs` (множество уже открывавшихся вкладок);
  - `:104-110` — сброс множества при смене сессии (у гостя и залогиненного разные
    наборы экранов);
  - `:296-320` — дети `IndexedStack` обёрнуты в
    `TickerMode(enabled: i == safeIndex, …)`, неоткрытые — `SizedBox.shrink()`.
- **Поведение:** открытая вкладка работает как раньше; уже посещённые остаются
  живыми (состояние, позиция скролла); непосещённые не строятся и не грузят
  данные. Анимации невидимых вкладок останавливаются.
- **Риск:** код, который рассчитывал на `initState` скрытой вкладки (например,
  «настройки» с зондированием зеркал), теперь срабатывает при первом визите —
  это и есть цель. Если где-то ждут сайд-эффект скрытой вкладки — искать там.
- **Проверить:** переключение вкладок до и после логина/логаута, возврат на
  вкладку (скролл и выбранные фильтры сохраняются), отсутствие сетевых запросов
  непосещённых вкладок в логе.

### 3.4. Бейдж непрочитанных больше не перестраивает shell

- **Причина:** `ref.watch(dmUnreadCountProvider)` стоял в `MenuScreen.build`,
  который возвращает `IndexedStack` с шестью экранами: любое входящее сообщение
  пересобирало все шесть поддеревьев.
- **Изменено:** `menu_screen.dart:363-430` — `_ShellNavBar` и `_ShellNavRail`
  (`ConsumerWidget`), плюс функция `withUnreadBadge(ref, items, index)`; сам
  `MenuScreen` счётчик больше не читает (`:194-197`), бейдж подставляется в
  панель навигации (`badge` для плитки «Чаты», индекс 2 у залогиненного).
- **Риск:** если чаты «свернулись» в «Ещё», бейдж повесится на плитку «Ещё»
  (индекс 2 в свёрнутом списке) — поведение деградирует, но не ломается.
- **Проверить:** новое сообщение с другого аккаунта → обновляется только панель.

### 3.5. Старт: Firebase и проверка пакета ушли за первый кадр

- **Причина:** `bootstrap()` ждал `FirebaseMessagingService().initialize()` с
  таймаутом 10 с и `PackageInfo.fromPlatform()` **до** `runApp()`.
- **Изменено:**
  - `lib/app/bootstrap.dart:229-247` — в `addPostFrameCallback` вызывается
    `unawaited(_initAfterFirstFrame())`; функция (`:242-256`) делает проверку
    пакета и FCM.
  - `lib/core/services/firebase_messaging_service.dart:56-85` — вместо
    `Completer`-а поле `Future<void>? _initFuture`:
    `initialize()` идемпотентен, `initializationFuture` теперь **запускает**
    инициализацию, а не отвечает «готово» раньше времени. Это важно: провайдер
    токена (`features/profile/providers/fcm_token_provider.dart:13-16`) ждёт
    `initializationFuture`; при прежнем геттере он получал `null` без попытки.
  - При ошибке `_initFuture` сбрасывается — следующий вызов пробует снова.
- **Риск:** диалог разрешений на уведомления (Android 13+) появляется после
  первого кадра — так и задумано. Токен FCM приходит позже, чем раньше, но
  синхронизация с бэкендом ждёт `initializationFuture`, а не таймер.
- **Проверить:** холодный старт (`adb shell am start -W`), приход пуш-уведомления
  на свежей установке (в том числе при открытии из уведомления), появление
  `fcm_token` в профиле.

### 3.6. Кэш декодированных картинок ограничен по памяти

- **Причина:** дефолт Flutter — 100 МиБ и 1000 картинок независимо от телефона.
- **Изменено:** `bootstrap.dart:249-277` — `_configureImageCache()`: ~4% физической
  памяти, зажатые в 32–128 МиБ, и не больше 300 картинок. Память читается
  `physicalMemoryBytes()` (`packages/mnd_player/lib/utils/device_memory.dart`,
  на Android — `/proc/meminfo`).
- **Риск:** при < 32 МиБ кэша на 2-ГБ устройстве часть миниатюр будет
  пере декодироваться при возврате на экран. Это осознанный размен против OOM.
- **Проверить:** `adb shell dumpsys meminfo` (`Graphics`) при прокрутке ленты.

### 3.7. Разбор больших ответов API — в изоляте

- **Причина:** `jsonDecode` полного каталога/ленты в UI-изоляте — фриз на сотни мс
  независимо от мощности устройства.
- **Изменено:** `core/services/api_service.dart:27-33` — порог 256 КБ,
  `:41-48` — `_decodeBody(response)`, `compute(_decodeJsonBytes, bytes)` выше
  порога; пять мест, где тело разбиралось, переведены на него. Ниже порога —
  разбор на месте (копирование в изолят дороже).
- **Риск:** для тела ~300 КБ накладные расходы копирования могут быть заметны;
  порог можно поднять.
- **Проверить:** открытие каталога на медленном устройстве (`flutter run
  --profile`, DevTools → CPU).

### 3.8. Каталог маркета: один запрос вместо двух

- **Причина:** `marketQuestsProviderNew` и `marketQuestsProviderPopular` делали
  `GET /quests` независимо и параллельно при открытии вкладки.
- **Изменено:** `features/market/providers/market_provider.dart:87-101` —
  `marketCatalogProvider` (сеть + парсинг один раз), оба провайдера берут из него
  и сортируют **копию** (`List<MarketQuest>.of(base)`).
- **Попутно исправлен баг:** фоллбэк «Выбора Миандера» сортировал закэшированный
  список провайдера **на месте** (`all.sort(...)`), ломая порядок у остальных
  полок; теперь тоже копия (`:126-131`).
- **Инвариант:** значение `FutureProvider` — read-only для потребителей. Любая
  сортировка/фильтрация — по копии (см. раздел 4).

### 3.9. Сокет: счётчики применяются пачкой, лента ограничена

- **Причина:** сервер шлёт `post_stats_updated` всем клиентам на каждый лайк
  платформы; клиент на каждое событие копировал список постов и перестраивал
  ленту. `new_wall_post` добавлял посты без предела.
- **Изменено:**
  - `features/community/providers/community_feed_provider.dart:46-57` —
    накопитель `_pendingStats` + `Timer` 250 мс; `:79-105` — `_flushStats()`
    применяет все счётчики одним изменением состояния; `:68-76` — таймер
    отменяется в `dispose`. `:118-124` — лента обрезается до 200 постов.
  - `features/wall/providers/wall_paginated_provider.dart:56-70, 86-118` — то же
    накопление для стены автора (там `new_wall_post` — no-op).
- **Поведение:** цифры лайков обновляются с задержкой ≤ 250 мс вместо мгновенно.
  Меньше одного изменения состояния на пачку событий.
- **Риск:** события, пришедшие в последние 250 мс перед уходом с экрана, могут не
  примениться (нотифаер диспозится) — при следующем открытии лента всё равно
  перечитывается.

### 3.10. Markdown: конфиг и разбор кэшируются

- **Причина:** `AppMarkdown.getConfig` создавал новый `MarkdownConfig` (10+
  конфигов, `TextStyle`, `BoxDecoration`) на каждый `build` каждой карточки, а
  `MarkdownBlock` из `markdown_widget` — `StatelessWidget`, который вызывает
  `MarkdownGenerator.buildWidgets` прямо в `build` (полный разбор текста).
- **Изменено** в `shared/widgets/app_markdown_config.dart`:
  - `:22-40` — кэш конфигурации по identity пары (`ColorScheme`, `TextTheme`);
  - `:165-250` — `AppMarkdownBlock` с кэшем разобранных виджетов по
    (текст, конфиг): 160 записей, при переполнении сбрасывается;
  - `:141-147` — `memCacheWidth` для картинок из markdown (ширина экрана в
    физических пикселях).
  - `shared/entity_links/entity_ref_card.dart:608-609` — `MeanderEntityMarkdown`
    рисует через `AppMarkdownBlock`.
- **Инвариант:** кэш хранит `List<Widget>` и переиспользует экземпляры. Это
  законно (виджеты иммутабельны), но `buildWidgets` не должен начать возвращать
  `GlobalKey` — в `markdown_widget-2.3.2+8` их нет (проверено grep).
- **Риск:** при смене темы identity конфига меняется, старые записи не
  используются и вытесняются сбросом. Тексты с одинаковым содержимым в разных
  местах делят один набор виджетов — это нормально.

### 3.11. `ExpandablePostText`: замер переполнения не на каждый build

- **Причина:** `TextPainter.layout` по всему тексту поста на каждый `build`
  (лента перестраивается на скролл и на socket-события).
- **Изменено:** `features/wall/widgets/expandable_post_text.dart:21-66` — замер
  кэшируется по (текст, ширина, `maxLines`, базовый стиль темы, `textScaler`),
  `:117-120` — используется закэшированная высота.
- **Инвариант:** ключ включает всё, что влияет на метрики. Добавляешь параметр
  вёрстки — добавь его в ключ.

### 3.12. Картинки: декод под размер тайла

- **Причина:** 19 `CachedNetworkImage` и 15 `Image.file` без ограничения декода:
  фото 12 Мп — ~48 МБ на кадр плюс загрузка текстуры в GPU при прокрутке.
- **Изменено:**
  - новые файлы `shared/widgets/image_decode_size.dart` (чистая функция
    `imageDecodeWidthFor`) и `shared/widgets/image_sizing.dart`
    (`imageDecodeWidth(context, divisor: …)`);
  - `features/wall/widgets/post_card.dart` — `memCacheWidth` в четырёх местах
    (полная ширина / половина при двух фото / половина в сетке 2×2);
  - `features/community/screens/post_comments_screen.dart` — два места;
  - `features/library/screens/my_library_screen.dart` — `cacheWidth` для
    `Image.network` и локального файла;
  - `features/resources/widgets/resource_cards.dart` — три превью;
  - `shared/widgets/app_markdown_config.dart` — картинки из markdown;
  - `packages/mnd_player/lib/widgets/content_display_factory.dart:2511-2524` —
    картинка узла (`cacheWidth`), `:2533-2545` — полноэкранный просмотр через
    `ResizeImage(FileImage, width: экран×2, allowUpscaling: false)`.
- **Риск:** на экранах с высоким DPR и маленьким тайлом картинка может выглядеть
  чуть мягче; предел снизу (`min: 200`) и множители подобраны так, чтобы этого
  не было на телефонах. `PhotoView` при зуме > 2× будет мыльнее — цена отказа от
  полноразмерного декода.

### 3.13. `LocalFileImage`: путь к файлу резолвится один раз

- **Причина:** `FutureBuilder(future: FileStorage.getFilePath(...))` прямо в
  `build` создавал новый Future на каждую перестройку — лишний кадр с заглушкой
  и мигание в сетках.
- **Изменено:** новый `shared/widgets/local_file_image.dart` (StatefulWidget,
  Future создаётся в поле состояния, пересоздаётся только при смене пути,
  поддерживает `cacheWidth`, `checkExists`, заглушку и `errorBuilder`).
  Используется в `resource_cards.dart` (3 места) и `my_library_screen.dart` (1).
- **Инвариант:** `checkExists: true` включается только там, где нужна разница
  между «файла нет» и «путь ещё не известен».

### 3.14. Игра: кэш проверки видимости айтема

- **Причина:** в `FutureBuilder`-ветке `ConditionalContentWrapper` на каждый
  `build` вызывались `ref.watch(gameStateProvider)` + `item.toJson()` +
  синхронный FFI `evaluateVisibility`.
- **Изменено:** `packages/mnd_player/lib/widgets/content_display_factory.dart:440-450`
  — поля-кэш; `:599-616` — пересчёт только если изменились
  `state`/`item`/`engine` (identity).
- **Инвариант:** `gameStateProvider` эмитит **новый объект** на каждое изменение
  (везде `state = state.copyWith(...)`), поэтому identity-сравнение корректно.
  Если появится мутация состояния на месте — кэш надо переделать на версию.

### 3.15. Игра: кэш разобранного markdown слоя заливки

- **Причина:** текст перестраивается на каждое изменение переменной и на каждый
  шаг «печатания»; `buildWidgets` разбирает строку заново. Плюс невидимый слой
  `reserved` (держит габарит) разбирается на каждом тике.
- **Изменено:** `content_display_factory.dart:1329-1347` — общий билдер,
  `:1370-1383` — для слоя без обводки вызов через `cachedFillMarkdown`;
  `:1432-1457` — кэш (24 записи) с ключом
  `questId \0 baseFontSize \0 fontFamily \0 текст`.
- **Инвариант:** кэшируется только слой **заливки** (`stroke == null &&
  !outlineOnly`), потому что его результат зависит только от текста и шрифтовых
  параметров. Обводка зависит от `Paint` — она не кэшируется. Добавляешь параметр
  стиля — добавляй в ключ.
- **Риск:** при смене темы/шрифта кэш не сбрасывается, но ключ меняется по
  `fontFamily`/`baseFontSize`; при 24 записях кэш и так очищается.

  (`mndAbis`), не дублировать литералами.

## 4. Инварианты, которые нельзя ломать

1. **Значения провайдеров read-only.** Сортировка/фильтрация — по копии
   (см. `market_provider.dart`); иначе ломаются другие полки и экраны.
2. **Кэши ограничены и сбрасываются при переполнении.** Кэши markdown/JSON/тем/
   выражений/видео — не «просто Map».
3. **Ключи кэшей включают всё, что влияет на результат.** Для markdown — текст,
   `questId`, размер и семейство шрифта; для замера текста — ширина, `maxLines`,
   стиль, `textScaler`.
4. **Identity-кэш состояния движка** валиден только пока `gameStateProvider`
   эмитит новые объекты (сейчас так).
5. **`TickerMode`/ленивые вкладки:** `_mountedTabs` сбрасывается при смене
   сессии; неоткрытые вкладки не должны требовать сайд-эффектов.
6. **FCM:** `initializationFuture` обязан **запускать** инициализацию, а не
   сообщать о готовности заранее.
7. **Декод картинок:** `cacheWidth`/`memCacheWidth` задаётся по реальному размеру
   слота (`imageDecodeWidth`), а не «на глаз»; верхний предел 1440/2048 — чтобы
   не вернуть полноразмерные декоды.
8. **Автосейв канваса** берёт тела нод **с диска** (свежие), а не из состояния.
9. **Один список ABI** в gradle (cargo-ndk и `abiFilters`).
10. **Не возвращать** `await` Firebase/`PackageInfo` до `runApp` и не включать
    максимальную частоту экрана по умолчанию.

## 5. Что осталось (по приоритету)

1. **Импорт `.mnd` и бэкапы в изоляте.** Сейчас PBKDF2 (15 000 итераций) + AES +
    `ZipDecoder` идут в UI-изоляте (`core/services/import_service.dart:82-176`).
    Правка требует вынести «дешифровка → zip → распаковка во временный каталог»
    в `Isolate.run`, возвращая наружу только пути (иначе архив копируется между
    изолятами). Риск высокий: это код восстановления данных, нужен прогон
    существующих тестов импорта на устройстве/в CI. Поэтому в этой ветке не
    трогали.
2. **`questsProvider` читает `config.json` всех квестов последовательно**
   (`features/quests/providers/quest_provider.dart:81-240`) — 100+ операций на
   eMMC. Безопасный вариант: батчи по 4 с `Future.wait`, но внутри цикла есть
   восстановление из бэкапа, HMAC и миграция — нужен прогон тестов
   `test/features/quests/*`.
3. **Каталог маркета без `limit`/пагинации** — требует продуктового решения о
   серверной сортировке полок.
4. **`SelectionArea` на каждый пост** — сознательно оставлено (выделение текста
   полезнее, чем выигрыш).
5. **media_kit/libmpv (~5,7 МБ на ABI)** и `quest_player_template.apk` в assets —
   продуктовые решения (видео в гайдах, офлайн-сборка APK).
6. **lint-шум в логах**: 88 `print(` в release. Механическая правка, не в горячем
   пути.

## 8. Что вошло в `main`, а что отложено (ревью 2026-11-13)

Ветка проверена на машине разработки (Flutter 3.47.9): `flutter analyze` даёт
те же 318 замечаний и 0 ошибок, что и `main` до вливания; `background_blur_test`
(29) и `image_sizing_test` (5) — зелёные. Влито:

- `perf(mnd_player)`: кэш AST выражений, декод картинок под экран, кэш
  `evaluateVisibility` по identity состояния, `GlassSurface` без `Future` в
  `build`, ограниченный кэш JSON в `FileStorage`, точечное чтение нод главой.
- `perf(main_app)`: старт без Firebase в первом кадре, ленивые вкладки +
  `TickerMode`, кэши markdown/темы/замера текста, декод картинок под тайл,
  пачки сокета, один запрос каталога, кэш картинок по памяти устройства.
- `perf(android)`: три ABI по умолчанию (`-PmndAbis` переопределяет).

Исключено и вынесено в отдельное изменение (меняет вид или поведение):

1. **Неявный блюр фона ноды на Android/iOS.** `defaultBackgroundBlurFor`
   убран: значение по умолчанию осталось 10 на всех платформах. Причина —
   редактор пишет `backgroundBlur` в файл только если автор трогал
   переключатель, а подсказка в редакторе обещает «10 по умолчанию»; отключение
   на мобиле меняло бы вид старых квестов и расходилось бы с десктопом.
   Правильное решение — пре-рендер размытого фона один раз на ноду.
2. **Частота экрана.** Дефолт «максимальная частота» не менялся, 60 Гц
   остаются выбором пользователя.
3. **Размытие заголовка карточки квеста на мобиле.** Осталось как было.
4. **Кэш видеоплееров.** Остался 3 плеера / 5 минут.
5. **`useLegacyPackaging=false` + `extractNativeLibs=false`.** Формат упаковки
   `.so` проверяется установкой поверх предыдущей сборки, отдельно от перфа.

Поправлено в ревью: удалён мёртвый дубль `shared/widgets/image_decode_size.dart`;
кэш markdown в игре вытесняет по одной записи (иначе «печатная машинка» чистила
его целиком каждый кадр); ширина декодирования картинок вошла в ключ кэша
markdown-конфига (поворот/ресайз окна); `FileStorage` обновляет порядок записи
при чтении (LRU); индекс бейджа «Чаты» ищется по самой плитке, а не по числу.
