# Потоковая раздача квеста

Веб-плеер раньше качал `.mnd` целиком и распаковывал **все** записи в память:
время до первого кадра и пик RAM росли вместе с объёмом медиа. Теперь квест
можно отдавать потоково: маленький текст‐бандл на старт, медиа — по требованию.

Нативная загрузка `.mnd` (кнопка «Скачать», библиотека, облако) не меняется.

## Эндпоинты (`crates/mnd-server`, префикс `/quests`)

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/quests/{id}/manifest` | JSON-манифест архива |
| GET | `/quests/{id}/boot` | `MND_ZIP_` + zip только с текстовой частью |
| GET | `/quests/{id}/boot.mnd` | то же самое (имя берётся из поля `boot` манифеста) |
| GET | `/quests/{id}/entry/{path}` | байты одной записи архива |
| GET | `/quests/{id}/file` | полный `.mnd` (как раньше) |

Доступ у всех — тот же, что у `/file`: опубликованный квест виден всем,
неопубликованный — только автору и админу. Служебные записи (`saves/`,
`editor_session.json`) наружу не выдаются и в манифест не попадают.

Потоковые маршруты вынесены из общего quest-лимита (60 запросов / 15 минут на
анонима): ленивая подгрузка — это десятки запросов на один квест.

### Манифест

```json
{
  "version": 1,
  "questId": "b0e6…",
  "contentHash": "…",
  "format": "legacy",
  "boot": "boot.mnd",
  "entries": [
    { "path": "res/images/bg.png", "kind": "image", "size": 12345,
      "sha256": "…", "boot": false }
  ]
}
```

`contentHash` — сводка записей (путь + размер + sha256), идёт в `ETag`.
`format` — `legacy` (в архиве `nodes.json`) или `per-node`
(`nodes/index.json` + тела). `boot` отмечает записи, попавшие в boot-бандл.

### Boot-бандл

Всегда содержит только текстовую часть: `config.json`, монолитный
`nodes.json`, `res/templates.json`, `res/metadata.json`,
`res/button_presets.json`, `scripts/**`, `_internal_scripts/**`,
`res/fonts/**`.

Для per-node архива монолитный `nodes.json` **синтезируется** из
`nodes/index.json` и тел нод (то же, что делает экспортёр в `mnd-core` для
старых плееров) — веб-плеер читает именно монолит.

### Ленивые записи

`/entry/{path}` распаковывает запись из `.mnd` при первом обращении в
`quests_files/{id}.d/{path}` (потоково в temp-файл, затем atomic rename) и
дальше отдаёт статикой с `ETag`/`Range`. Полного дублирования диска нет —
материализуется только то, что реально запросили.

Артефакты (`{id}.manifest.json`, `{id}.boot.mnd`, `{id}.d/`) собираются при
публикации и, если их нет (квесты, опубликованные раньше), — при первом
запросе. Удаление квеста чистит их вместе с `.mnd`.

Шифрованные архивы (`MND_ENC2`/`MND_SEC_`) потоково не разбираются: такие
квесты доступны только полной загрузкой (их и так не открывает веб-плеер).

## Nginx

Веб-плеер живёт под COEP, поэтому качает квест с **того же origin** через
`/quest-src/`. Полный архив там отдаётся статикой, а потоковые пути нужно
проксировать в бэкенд:

```nginx
# /quest-src/<uuid>.mnd  -> статика, как раньше
# /quest-src/<uuid>/manifest|boot|entry/<path> -> API
location ~ ^/quest-src/(?<qid>[0-9a-f-]{36})/(manifest|boot(\.mnd)?|entry/.*)$ {
    proxy_pass http://127.0.0.1:3100/quests/$qid/$1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

Формат ответов у Node-бэкенда пока отсутствует; клиент сам откатывается на
полную загрузку, если манифест недоступен (см. ниже), так что раскатка
безопасна.

## Клиент

`apps/web_player`:

* `QuestAssets` — общий интерфейс ассетов; `QuestBundle` (полный архив) и
  `HttpQuestAssets` (поток) его реализуют.
* `openQuestAssets(url)` пробует `{base}/manifest`, где `base` — URL квеста без
  `.mnd` (переопределяется параметром `base=`). Успех → boot + ленивые записи;
  иначе — прежний `loadQuestBundle(url)`. Отключить потоково можно `?stream=0`.
* `assetBytes(...)` остаётся **синхронным** (читает из кэша), а
  `prefetch(...)` догружает ресурсы ноды при входе в неё — вызовы из виджетов
  не менялись.
* Байты кэшируются в памяти (LRU), шрифты приходят в boot и грузятся сразу.
